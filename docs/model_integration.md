# Model integration status

The default Isaac conversion now uses the [X650 CAD-frame model](x650_model_integration.md), with its own URDF, nominal inertials, X650 collision proxies, and STEP-derived frame visual. The details below document the preserved X500 source and legacy conversion. Use `./scripts/convert_model.sh --airframe x500` to regenerate it.

`scripts/prepare_assets.py` resolves every URDF visual mesh, checks the single root link, verifies 90 named STEP parts against the supplied assembly metadata and both STEP assemblies, and writes SHA-256 hashes to `assets/generated/asset_manifest.json`. It never changes source assets or silently attaches the 115 MB multi-part STEP to a link. Isaac Sim 6.0.1 RC's URDF importer was executed successfully on this host using NVIDIA driver 580.178.04 and an RTX 4070 Laptop GPU (8 GB). The source URDF and meshes were not modified.

The URDF supplies link/joint structure, collision proxies and estimated inertials; STEP supplies detailed visual geometry in millimeters. The current Isaac conversion uses the supplied STL tessellations already assigned to URDF links, with 0.001 visual scale. `scripts/convert_model.sh` invokes the version-matched URDF importer with fixed-joint merging disabled, a floating base, and URDF collision proxies rather than collision-from-visuals. Its first run produced `assets/generated/isaac_6_0_x500_v6/x500_v2_sprayer/x500_v2_sprayer.usda`; repeated imports use unique suffixed directories, and the manifest always points to the latest. The generated stage was opened and checked for `base_link`, `nozzle_head`, `trigger_crank`, and `spray_tip` names. `scripts/run_isaac_scene.sh` referenced the USD in a baseline site and advanced physics time 1.000 s in 60 headless frames. The estimated complete-aircraft mass and inertia support simulator tuning; measured values are required before hardware controller tuning.

The source bundle carries a partial map: `assembly_data.json` and `mass_breakdown.csv` assign 90 named payload/mount parts to `rail_mount`, `landing_risers`, `sprayer_body`, `trigger_crank`, or `nozzle_head`. Those 90 product names occur in the 91-label payload STEP export. They are now explicit in `config/asset_mapping.yaml` and checked by `prepare_assets.sh`. The large root STEP has 336 product labels; its other aircraft parts still need reconciliation with the URDF `base_link`. STEP CAD solids are not yet freshly tessellated by the Isaac pipeline; it consumes the supplied link-local STLs.

A prototype Isaac force controller now uses this import for simulated takeoff and site flight. It adds a documented 1.025 kg battery/hardware estimate to the imported base link, updates its inertia and aggregate center of mass, and applies four rotor forces at the URDF motor positions. The [propulsion calibration](propulsion_calibration.md) uses a published 16 V bench curve as a proxy; actual complete-aircraft mass, thrust and motor lag remain unmeasured. A path-tracking success does not establish hardware flight readiness.
